### Architecture: The "Agentic CLI" Pattern

To move from a simple chat interface to a full code-generation engine, you need an **Orchestrator-Worker** pattern.

*   **The Orchestrator (The CLI):** Captures user input, manages context, and decides *what* to do.
*   **The Planner (The LLM):** Parses the natural language to determine the intent (e.g., "User wants to fetch data from a SOAP endpoint").
*   **The Generator (The LLM):** Writes the specific Python/Bash script to perform the task.
*   **The Executor (The Runtime):** Safely runs the generated code and returns output.

---

### Step 1: The Tech Stack

Since you are looking for a robust CLI solution:
*   **Language:** Python (best for libraries like `requests`, `zeep` for SOAP, `sqlalchemy` for CRUD).
*   **CLI Framework:** `Typer` or `Click`.
*   **LLM Interface:** `Ollama` Python library or `langchain-ollama`.

### Step 2: Natural Language Parsing (The Router)

You cannot feed every prompt directly to a code generator. You need a "Router" step. This is a system prompt that classifies the user's intent.

**System Prompt for the Router:**
> "You are an AI routing agent. Analyze the user's request and categorize it into one of these JSON formats:
> 1. `FILE_OP`: Reading or writing local files.
> 2. `API_REST`: Consuming a REST API.
> 3. `API_SOAP`: Consuming a SOAP service.
> 4. `DB_CRUD`: Database operations.
> 5. `BATCH`: Bulk processing.
> Output only the JSON category and a summary of required parameters."

### Step 3: The Code Generation Engine

Once the router identifies the intent, you send the request to a "Coder" agent with specific tools available.

#### Implementation for Different Capabilities

**A. Direct File Access**
*   *Strategy:* Do not let the LLM write `open('file.txt', 'w')` blindly (security risk). Define a tool set.
*   *Code Gen Instruction:* "Use the `FileManager.read()` and `FileManager.write()` methods provided in the context."

**B. REST Capabilities**
*   *Library:* `requests` or `httpx`.
*   *Prompt Engineering:* "Generate a Python script using the `requests` library to [USER REQUEST]. Include error handling for status codes."

**C. SOAP Capabilities**
*   *Library:* `zeep` (Python SOAP client).
*   *Prompt Engineering:* "Generate a Python script using `zeep` to connect to WSDL [URL] and call method [METHOD]. Parse the response object."

**D. CRUD & Batch**
*   *Strategy:* The LLM should generate data-processing scripts.
*   *Batch Logic:* "Use a `for` loop or `pandas` dataframe to iterate over the list of items and perform the operation."

### Step 4: Workflow Implementation (Pseudo-Code)

Here is how your `ai.sh` or Python backend logic should look:

```python
import ollama
import json
import subprocess

def get_intent(user_prompt):
    # Step 1: Ask LLM what the user wants
    response = ollama.chat(model='llama3', messages=[
        {'role': 'system', 'content': 'You are a router. Output JSON intent.'},
        {'role': 'user', 'content': user_prompt}
    ])
    return json.loads(response['message']['content'])

def generate_code(intent, user_prompt):
    # Step 2: Generate the script based on intent
    system_instruction = f"""
    You are a Python expert. Write a python script to:
    {user_prompt}

    Constraints:
    - If type is FILE_OP: use standard 'open' functions.
    - If type is API_SOAP: use 'zeep' client.
    - If type is API_REST: use 'requests'.
    - Print the final result to stdout.
    """

    response = ollama.chat(model='codellama', messages=[
        {'role': 'system', 'content': system_instruction},
        {'role': 'user', 'content': user_prompt}
    ])
    return response['message']['content']

def execute_script(script_code):
    # Step 3: Sandboxed execution (Docker or restricted subprocess)
    # For simplicity, we write to a temp file and run it
    with open('temp_exec.py', 'w') as f:
        f.write(script_code)

    result = subprocess.run(['python3', 'temp_exec.py'], capture_output=True, text=True)
    return result.stdout

# Main Loop
user_input = "Fetch the user list from the SOAP endpoint and save it to users.json"
intent = get_intent(user_input)
code = generate_code(intent, user_input)
output = execute_script(code)
print(output)
```

### Step 5: Extending the Project

To make this a reality for your project:
1.  **Define "Tools"**: Create a JSON/YAML config file defining exactly which APIs and DB schemas the AI is allowed to access.
2.  **Context Injection**: When the user asks to "Update Project X", your CLI should first scan the directory tree and inject the file structure into the prompt so the AI knows what files exist.
3.  **Safety**: Wrap the execution in a Docker container so that if the AI generates `rm -rf /`, it only wipes the container, not your host machine.

This architecture turns your CLI from a simple chatbot into a **dynamic DevOps agent** capable of handling complex protocols like SOAP and batch processing based on natural language commands.
